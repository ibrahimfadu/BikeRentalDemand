## 📌 Problem Statement

Bike-sharing systems need accurate demand forecasts to manage bike availability, storage, and relocation. Our goal is to predict the **hourly count of bike rentals** and minimize the **Root Mean Squared Logarithmic Error (RMSLE)**:

```
RMSLE = sqrt(mean((log(p + 1) - log(a + 1))^2))
```

where `p` is the predicted count and `a` is the actual count. Lower is better.

---

## 📊 Dataset

- **Source:** [Kaggle — Bike Sharing Demand](https://www.kaggle.com/c/bike-sharing-demand)
- **Training set:** 10,886 hourly observations
- **Test set:** 6,493 hourly observations
- **Features:** datetime, season, holiday, workingday, weather, temp, atemp, humidity, windspeed
- **Target:** `count` (total rentals per hour)

Download `train.csv` and `test.csv` from Kaggle and place them in the `data/` folder.

## 🧠 Approach

### Feature Engineering

1. **Datetime decomposition** — Split `datetime` into `month`, `dayofweek`, and `hour`
2. **Peak-hour indicator** — Binary flag for commute hours (weekday 7–9 AM & 5–7 PM; weekend 10 AM–6 PM)
3. **Feature removal** — Dropped `holiday` (no signal) and `temp` (collinear with `atemp`)

### Models Evaluated (with 10-Fold CV)

| Model | CV RMSLE |
|---|---|
| Split Regression (reg + cas) | **0.3928** |
| Random Forest | **0.3985** |
| CTree (DecisionTree substitute) | 0.4469 |
| GBM (Gradient Boosting) | 0.5016 |
| Stacking Ensemble | 0.5624 |
| SVR (RBF kernel) | 0.8452 |
| GLMNet (Elastic Net) | 1.1629 |
| PCR | 1.1817 |
| Linear Regression | 1.1855 |

**Best model:** Split Regression / Random Forest (~0.39 CV RMSLE)

---

## 📈 Key Findings

- **Time-of-day dominates.** `peak_hour` + `hour` account for ~64% of feature importance.
- **Weather matters, but less.** `atemp` and `humidity` are secondary predictors.
- **Tree-based models win.** Linear and kernel models struggled with non-linear demand patterns.
- **Split regression performed on par with Random Forest** — contradicting the reference paper, where it was worse.
